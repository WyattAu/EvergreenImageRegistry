# FIPS 140-3 Compliance for Evergreen Image Registry

## Overview

FIPS 140-3 is the current U.S. federal standard for cryptographic module validation, replacing FIPS 140-2.
This document describes how to build FIPS-compliant variants of EIR container images.

## What FIPS 140-3 Requires for Container Images

1. **Validated Cryptographic Modules**: All cryptographic operations must use FIPS-validated modules
2. **Self-Tests**: Cryptographic modules must run power-on self-tests (POST) before use
3. **Algorithm Restrictions**: Only approved algorithms (AES-GCM, SHA-256/384/512, RSA 2048+, ECDSA P-256+) are permitted
4. **Key Management**: FIPS-compliant key generation, storage, and destruction
5. **Physical/Logical Boundaries**: Container isolation provides logical boundary; additional controls for key storage

## Approved Cryptographic Modules

| Module | Validation | Used By |
|--------|-----------|---------|
| BoringCrypto (BoringSSL) | FIPS 140-2 Cert #4140, revalidating under 140-3 | Go images (via GOEXPERIMENT=boringcrypto) |
| OpenSSL 3.x FIPS Provider | FIPS 140-2 Cert #4230, revalidating under 140-3 | C/C++/Java images |
| AWS-LC | FIPS 140-2 Cert #4029, revalidating under 140-3 | Alternative to BoringSSL |
| NSS | FIPS 140-2 Cert #278/889/1742 | Firefox/Mozilla-derived projects |

## How to Build FIPS-Compliant Variants

### Approach A: Go Images with BoringCrypto

BoringCrypto is the FIPS-validated cryptographic module bundled with BoringSSL. It holds FIPS 140-2 Certificate #4140 and is being revalidated under FIPS 140-3.

**Dockerfile Template (Go with BoringCrypto):**

```dockerfile
FROM golang:1.24-bookworm AS builder
ARG VERSION
ARG TARGETARCH

RUN apt-get update && \
    apt-get install -y --no-install-recommends git ca-certificates && \
    rm -rf /var/lib/apt/lists/*

RUN git clone --depth 1 --branch "v${VERSION}" \
    https://github.com/example/project /src

# BoringCrypto build - CGO_ENABLED=1 is MANDATORY
RUN cd /src && \
    CGO_ENABLED=1 GOOS=linux GOARCH=${TARGETARCH} \
    GOEXPERIMENT=boringcrypto \
    go build -ldflags="-s -w" -o /app/binary ./cmd/binary

FROM debian:bookworm-slim
COPY --from=builder /usr/local/lib/libcrypto.so* /usr/local/lib/
COPY --from=builder /usr/local/lib/libssl.so* /usr/local/lib/
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=builder /app/binary /binary

# FIPS mode activation
ENV GOLANG_FIPS=1
ENV LD_LIBRARY_PATH=/usr/local/lib

USER 65532:65532
ENTRYPOINT ["/binary"]
```

**Critical Requirements:**
- `CGO_ENABLED=1` is mandatory - BoringCrypto cannot build with CGO_ENABLED=0
- `GOEXPERIMENT=boringcrypto` must be set at build time
- Final image cannot use `FROM scratch` - BoringCrypto dynamically links against glibc
- `GOLANG_FIPS=1` must be set at runtime to activate FIPS mode
- Switch from scratch to `debian:bookworm-slim` or `wolfi-base` for glibc

**Runtime Verification:**

```bash
# Verify BoringCrypto is active
GOLANG_FIPS=1 /binary --version
# Binary will refuse non-FIPS algorithms if BoringCrypto is active

# Verify FIPS mode via crypto/tls
echo 'package main; import ("crypto/tls"; "fmt"); func main() {
    fmt.Println(tls.VersionName(tls.VersionTLS13))
}' | go run -
```

### Approach B: C/C++ Images with OpenSSL FIPS Provider

OpenSSL 3.0+ uses a modular provider architecture. The FIPS provider is FIPS 140-2 validated (Certificate #4230).

**Dockerfile Template (OpenSSL FIPS):**

```dockerfile
FROM debian:bookworm-slim AS builder

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        build-essential wget ca-certificates && \
    rm -rf /var/lib/apt/lists/*

# Build OpenSSL 3.0.x with FIPS provider
RUN wget https://www.openssl.org/source/openssl-3.0.15.tar.gz && \
    tar xzf openssl-3.0.15.tar.gz && \
    cd openssl-3.0.15 && \
    ./Configure --prefix=/usr/local/ssl/fips \
                --openssldir=/usr/local/ssl/fips \
                enable-fips && \
    make -j$(nproc) && \
    make install && \
    make install_fips

# Build application linked against FIPS OpenSSL
RUN cd /src && \
    ./configure --with-ssl=/usr/local/ssl/fips && \
    make -j$(nproc) && \
    make install

FROM debian:bookworm-slim
COPY --from=builder /usr/local/ssl/fips /usr/local/ssl/fips
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/
COPY --from=builder /src/app /usr/local/bin/app

# FIPS configuration
ENV OPENSSL_CONF=/etc/ssl/fipsmodule.cnf
RUN echo 'config_diagnostics = 1\n\
openssl_conf = openssl_init\n\
.include /usr/local/ssl/fips/fipsmodule.cnf\n\
[openssl_init]\n\
providers = provider_sect\n\
alg_section = algorithm_sect\n\
[provider_sect]\n\
fips = fips_sect\n\
base = base_sect\n\
[base_sect]\n\
activate = 1' > /etc/ssl/fipsmodule.cnf

USER 65532:65532
ENTRYPOINT ["/usr/local/bin/app"]
```

**Verification:**

```bash
openssl list -providers
# Expected output:
# fips
#   name: OpenSSL FIPS Provider
#   status: active
```

### Approach C: Envoy with Built-in FIPS

Envoy uses BoringSSL which includes the BoringCrypto FIPS module natively.

**Dockerfile (Envoy FIPS):**

```dockerfile
FROM debian:bookworm-slim AS builder

# Download official FIPS-validated Envoy binary
ARG ENVOY_VERSION=1.38.0
RUN wget -q https://github.com/envoyproxy/envoy/releases/download/v${ENVOY_VERSION}/envoy-${ENVOY_VERSION}-linux-x86_64 \
    -O /usr/local/bin/envoy && \
    chmod +x /usr/local/bin/envoy

FROM debian:bookworm-slim
COPY --from=builder /usr/local/bin/envoy /usr/local/bin/envoy
COPY --from=builder /etc/ssl/certs/ca-certificates.crt /etc/ssl/certs/

# BoringCrypto self-tests on startup - no additional env vars needed
USER 65532:65532
ENTRYPOINT ["/usr/local/bin/envoy"]
```

## Build Configuration Changes

### Makefile Integration

```makefile
# FIPS build targets
FIPS_VARIANT ?= false

ifeq ($(FIPS_VARIANT),true)
  DOCKER_BUILD_ARGS += --build-arg FIPS_ENABLED=1
  DOCKER_BUILD_ARGS += --build-arg GOEXPERIMENT=boringcrypto
  GO_BUILD_FLAGS += CGO_ENABLED=1 GOEXPERIMENT=boringcrypto
  FINAL_BASE = debian:bookworm-slim
else
  FINAL_BASE = scratch
endif

build-fips:
	docker buildx build \
		--build-arg VERSION=$(VERSION) \
		--build-arg FIPS_ENABLED=1 \
		--target fips \
		-t $(IMAGE_NAME):$(VERSION)-fips \
		.
```

### CI/CD Pipeline Changes

```yaml
# .github/workflows/build-fips.yml
name: Build FIPS Variants
on:
  push:
    branches: [main]
    paths: ['images/*/Dockerfile']

jobs:
  build-fips:
    strategy:
      matrix:
        image: [postgres, redis, nginx, envoy, vault]
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Build FIPS variant
        run: |
          docker buildx build \
            --build-arg FIPS_ENABLED=true \
            --label "evergreen.fips=true" \
            --label "evergreen.fips.module=boringcrypto" \
            -t ghcr.io/wyattau/evergreenimageregistry/${{ matrix.image }}:$(cat VERSION)-fips \
            images/${{ matrix.image }}/

      - name: Verify FIPS module
        run: |
          docker run --rm \
            -e GOLANG_FIPS=1 \
            ghcr.io/wyattau/evergreenimageregistry/${{ matrix.image }}:$(cat VERSION)-fips \
            /verify-fips.sh
```

## Testing Requirements

### NIST Test Vectors

FIPS validation requires passing Known Answer Tests (KAT) for each algorithm:

#### AES-GCM Test Vectors

```bash
# AES-128-GCM KAT (from NIST SP 800-38D)
openssl enc -aes-128-gcm -K <key> -iv <iv> -in <plaintext> -out <ciphertext> -nosalt
# Verify against NIST test vector output

# Automated test script
#!/bin/bash
# test-fips-aes.sh
set -euo pipefail

TEST_VECTORS=(
  "key:00000000000000000000000000000000 iv:000000000000000000000000"
  "key:feffe9928665731c6d6a8f9467308308 iv:cafebabefacedbaddecaf888"
)

for vec in "${TEST_VECTORS[@]}"; do
  # Run KAT and verify output matches NIST reference
  echo "Testing: $vec"
  # ... verification logic
done
```

#### SHA-256 Test Vectors

```bash
# SHA-256 KAT (from NIST FIPS 180-4)
echo -n "abc" | openssl dgst -sha256
# Expected: ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad

echo -n "abcdbcdecdefdefgefghfghighijhijkijkljklmklmnlmnomnopnopq" | openssl dgst -sha256
# Expected: 248d6a61d20638b8e5c0269303f107232dddda0ed0861362f8f58f07
```

#### RSA Test Vectors

```bash
# RSA-2048 PKCS#1 v1.5 KAT
openssl rsa -in test_key.pem -text -noout | grep "Public-Key"
# Verify key size is 2048 bits minimum

# RSA-OAEP KAT
openssl rsautl -encrypt -oaep -inkey test_key.pem -in test_data.bin -out encrypted.bin
openssl rsautl -decrypt -oaep -inkey test_key.pem -in encrypted.bin -out decrypted.bin
diff test_data.bin decrypted.bin
```

### FIPS Mode Self-Test Verification

```bash
# verify-fips.sh - Run inside container
#!/bin/sh
set -e

echo "=== FIPS Module Verification ==="

# 1. Check OpenSSL FIPS provider
if command -v openssl >/dev/null 2>&1; then
  openssl list -providers 2>/dev/null | grep -q "fips" && \
    echo "[PASS] OpenSSL FIPS provider active" || \
    echo "[FAIL] OpenSSL FIPS provider not found"
fi

# 2. Check Go BoringCrypto (if applicable)
if [ -n "${GOLANG_FIPS:-}" ]; then
  # Attempt FIPS-only operation
  /binary --verify-fips 2>/dev/null && \
    echo "[PASS] BoringCrypto FIPS mode active" || \
    echo "[FAIL] BoringCrypto FIPS mode not active"
fi

# 3. Verify TLS connections use FIPS algorithms
if command -v openssl >/dev/null 2>&1; then
  # Test TLS 1.3 with AES-GCM
  openssl s_client -connect localhost:443 -tls1_3 -cipher TLS_AES_256_GCM_SHA384 \
    </dev/null 2>/dev/null && \
    echo "[PASS] TLS 1.3 with AES-GCM working" || \
    echo "[WARN] TLS test skipped (no server)"
fi

# 4. Check that non-FIPS algorithms are rejected
if command -v openssl >/dev/null 2>&1; then
  # DES should be rejected in FIPS mode
  echo "test" | openssl enc -des -nosalt 2>/dev/null && \
    echo "[FAIL] DES should be rejected in FIPS mode" || \
    echo "[PASS] Non-FIPS algorithms correctly rejected"
fi

echo "=== Verification Complete ==="
```

## Important Caveats

1. **Module vs. Module+Mode**: FIPS validation covers the cryptographic module, not the entire application. Full system validation requires additional steps.

2. **Scratch Limitation**: BoringCrypto requires glibc for dynamic linking. Images using `FROM scratch` must switch to a glibc-based image for FIPS variants, increasing image size by ~20-50MB.

3. **CGO Requirement**: `CGO_ENABLED=1` is non-negotiable for BoringCrypto. Cross-compilation becomes more complex and build times increase.

4. **OpenSSL 3.x FIPS Provider**: Must be installed and activated via `OPENSSL_CONF`. Without the configuration file pointing to the FIPS module, OpenSSL uses the default (non-FIPS) provider.

5. **FIPS 140-2 to 140-3 Transition**: The industry is transitioning. BoringCrypto and OpenSSL 3.x FIPS provider are being revalidated under FIPS 140-3. Plan for this transition.

6. **Enterprise vs. Community**: Some products (Vault, Consul, MongoDB) only provide certified FIPS builds in their Enterprise editions. Community FIPS builds use the same modules but lack formal certification.

## Quick Reference

### Environment Variables

```bash
# OpenSSL FIPS
OPENSSL_CONF=/etc/ssl/fipsmodule.cnf

# Go BoringCrypto
GOLANG_FIPS=1
GOEXPERIMENT=boringcrypto

# Java (Keycloak)
JAVA_OPTS="-Djava.security.properties=/etc/java/security.fips.properties"
JAVA_OPTS="-Dquarkus.ssl.native-fips=true"
```

### Build Flags

```bash
# Go with BoringCrypto
CGO_ENABLED=1 GOEXPERIMENT=boringcrypto go build -o binary ./cmd/binary

# OpenSSL with FIPS
./Configure --prefix=/usr/local/ssl/fips --openssldir=/usr/local/ssl/fips enable-fips

# nginx with FIPS OpenSSL
./configure --with-openssl=/usr/local/ssl/fips --with-openssl-opt=enable-fips

# Envoy with FIPS (Bazel)
bazel build --config=fips //:envoy
```
